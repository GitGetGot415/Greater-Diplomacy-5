SAVED DATA MIGRATIONS
====================

Migration means conversion from an older Greater Diplomacy 5 (GD5) data format to the current format.
data/migrations.py owns older GD5 identifiers, conversions, and load repairs.
Save imports from other games belong in their separate translation modules.
Greater Diplomacy 4 (GD4) and Greater Diplomacy Hex Edition are separate games, not older GD5 versions.

OWNERSHIP
---------

Keep GD5 migration rules in data/migrations.py.
Keep GD4 conversion rules in map_logic/gd4_translation.py.
Keep Greater Diplomacy Hex Edition conversion rules in map_logic/gdhex_translation.py.
Keep current settings fields and defaults in data/io/settings_schema.py.
Keep current gameplay rules and validation in their shared rule modules.
Keep saved-file access, compression formats, and storage synchronization in their input and output modules.

Existing migration imports from queries, settings_schema, load_map, and deal still work.
Those names refer to the central implementation. They do not contain duplicate conversion rules.

OLDER IDENTIFIERS AND FIELDS
----------------------------

Older country records can contain allied_with. Loading discards this obsolete field.
It does not create factions or change existing faction and subject relationships.
Country caches, saves, history, and both multiplayer systems use the same removal rule.
Current country records and the country summary do not include a direct-alliance list.

Settings accept api_key as gemini_api_key and ollama_api_key as ollama_base_url.
They accept music_speed and sfx_speed as music_pitch and sfx_pitch.
LING becomes OPENROUTER. ling_api_key and ling_model become openrouter_api_key and openrouter_model.
Writers use current names. Positional settings slots do not change.

Library loading converts AEROSPACE to AIR and Aerospace to Air.
Research and unit IDs stay unchanged in saves and multiplayer files.
Unnumbered aircraft become level I in unit records, including transported aircraft.
Production queues, custom production choices, and upgrade targets use the same name conversion.
Old scripted Spawn Unit actions also accept unnumbered names.
Research levels and progress remain unchanged.

Older aircraft Trucks unpack on land or become Convoys at sea, preserving identity and health fraction.
Old Truck conversion orders become Convoy orders on a coast and cancel inland.
Keep land paths only when queries.air_unit_can_move_on_ground permits them.
Older patrols without a priority use WEAKEST.
Cargo identity and stat repairs include air_cargo records.

Older puppet-release entries without release_type use Integrated.
Older tournament moves can supply release requests in the country-record queue.

LOAD ORDER
----------

Settings and library caches convert older names when they receive data.
Current settings keys take priority over older keys, including empty strings.
Library reloads keep shared dictionaries in place.

Map loading restores country templates before country-dependent rules run.
It applies province overlays before province queue conversion.
It converts aircraft names before unit stats and aircraft orders.
Unit stat conversion preserves health fractions and the existing version check.
Aircraft corrections also apply when the saved version equals the current version.
Faction roster repair occurs before faction pre-war maps are initialized.

Older research and production countdowns convert when processing reaches their entries.
Their existing timing and field precedence stay unchanged.
Scripted-event forecasts read older fields without changing saved state.
The event editor and event execution use the same conversion helpers.

MULTIPLAYER
-----------

Tournament readers use the central helpers for older payloads and release requests.
Older aircraft snapshots provide only order and name drafts for host validation.
The host still checks identity, session, turn, duplicates, permissions, costs, and targets.
Real-time commands still use server validation and filtered snapshots.
Migration does not grant permission to a client.

ADDING A MIGRATION
------------------

1. Add the GD5 conversion and older identifiers to data/migrations.py.
2. Call the helper at the required data boundary.
3. Preserve unknown valid fields and references held by other modules.
4. Keep conversion safe to repeat where the existing format permits it.
5. Test older data, current data, repeat conversion, and a save/load round trip.
6. Test affected multiplayer validation and player modes.
7. Check build manifests when adding runtime files.
