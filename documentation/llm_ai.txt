LLM AI
======

LLM means large language model. AI means artificial intelligence.
UI means user interface.
The model layer selects legal actions and writes messages.
Rule-based AI supplies the candidates and checks their legality.
The model cannot create an action that the rules forbid.
Diplomatic candidates pass shared availability checks in map_logic/diplomacy/action_definitions.py before model selection.

See documentation/non_llm_ai.txt for rule-based AI, shared game rules, and message metadata.
See documentation/ai_movement.txt for rule-based unit-order planning.
See documentation/diplo_stuff.txt for diplomacy timing and effects.

LLM MODULES
-----------

map_logic/ai/ contains these model components:

ai_letters.py
    Letters between countries and each country's private notebook.
ai_director.py
    Model selection from legal candidates.
ai_settings.py
    Provider, model, and API-key settings.
ai_handler.py
    Model providers, request cancellation, and turn IDs.
ai_activity.py
    What each model worker thread is doing, for the turn loading screen.
ai_llm_runner.py
    Model batches, phase budgets, cancellation, and progress.
    Progress counters use session state. AI computation data remains separate from presentation.
ai_prompts.py
    Shared context, prompt text, voice rules, and response-library access.
ai_evaluation.py, ai_diplomacy.py
    Connect model choices and proposal replies to shared AI rules.
    Selected requests use the shared diplomacy lifecycle and stable request references.
    Budget cancellation, shared prompts, fallback behavior, and fairness rotation retain their existing rules.

OPENROUTER SETTINGS
-------------------

Select OpenRouter in Settings to enter an OpenRouter API key and model ID.
The model field accepts other OpenRouter models.
Each provider's model field has a Default button.
Default sets that provider's model to its value in data/json/starting_defaults.json.
The game never replaces a saved model. A saved model that the provider retired stays until the player changes it.
The provider ID is OPENROUTER. Its settings keys are openrouter_api_key and openrouter_model.
Use OLLAMA for installed local models.
Its URL setting is ollama_base_url.

IMMERSION LEVELS
----------------

Select an immersion level with the red buttons in Settings.
The ? button for LLM AI explains the model's role and these levels.
Its text is SETTINGS_AI_INFO_TEXT in screens/menus/settings.py. Update it when a level changes.

OFF
    No model calls. Replies use the response library.

LITE
    The model replies only to custom messages written by a human.

FULL
    The model handles diplomacy that involves a human.
    AI-to-AI messages use the response library.

MAJOR
    FULL behavior, plus model control for major countries.
    These include leading powers, faction leaders, and countries bordering or fighting a human.

ABSOLUTE
    Every AI country can use the model.

At MAJOR and ABSOLUTE, model-driven countries also write letters. See LETTERS.

The per-country nation_data["llm_tier"] setting can override the immersion level.
Its values are ALWAYS, NEVER, and AUTO.

MODEL DECISIONS
---------------

1. Select actions from a country's scored legal candidates.
   A country receives its candidate list once per turn.
   AI_MAX_ACTIONS_PER_TURN limits the selected actions.
   The model selects at most one action per country and at most one faction request.
   The same reply supplies their message text.
   The prompt includes the country's notebook.
   Countries with no candidates do not need a call.
   At ABSOLUTE, a country with one candidate still gets a call for its wording.

   A model-driven country also receives its own-initiative candidates.
   These are proposals to its recent correspondents that no rule-based section offered:
   faction invitations and requests, new factions, trades, military access, calls to arms, joined wars, and peace terms.
   AI_CORRESPONDENTS_MAX limits the countries. A country can have several of these candidates.
   They pass the same availability, cooldown, and pending-request checks as other candidates.
   The rule-based fallback never selects them, so a skipped or failed call takes the staff's choice.

2. Decide whether to accept a proposal where the rules permit a choice.
   Fixed restrictions, such as an integrated puppet's trade restriction, remain binding.
   The model can override a rule-based recommendation, but cannot override legality.

3. Write letters and keep a notebook. See LETTERS.

The game discards illegal model requests.
A rumor in the global log can still show the attempted action.

Each request also sends a reply schema: a JSON Schema description of the reply's fields and their allowed values.
ai_director.reply_schema, ai_letters.reply_schema, ai_prompts.reply_schema, and ai_prompts.MESSAGE_SCHEMA build them.
A reply schema lists the allowed option IDs, letter recipients, actions, targets, and opinion limits.
Only Ollama receives the reply schema. Ollama enforces it during generation for models that match OLLAMA_JSON_SUPPORTED_MODELS.
Other Ollama models get no format.
Hosted providers keep their plain JSON mode. Their support for reply schemas differs by provider and model.
Also, a reply schema that differs for each country could stop a hosted provider from reusing the shared prefix.
The game still checks every reply, whether or not a reply schema constrained it.
ai_prompts.REPLY_ACTIONS supplies both the prompt's action list and the reply schema's action list.

MODEL TEXT AND MESSAGE METADATA
-------------------------------

ai_prompts.VOICE_RULE requires first-person plural speech.
The sender must not refer to its own country in the third person.
A reply that starts by naming its sender falls back to library text.

The llm field marks model-authored text.
_reply and the director's per-candidate messages set it where they create the text.
Provider error text does not set it.
It follows the message through pending_diplomacy into both inbox copies.
The spectator overview marks those rows orange.
Older messages without this field remain ordinary messages.

See documentation/non_llm_ai.txt for response-library lookup and shared message fields.

LETTERS
-------

AI countries talk to each other only through inbox letters, the same mail that players use.
Every model-driven AI country can write. The letter phase runs once per turn, before the proactive pass.
Letters follow the players' message timing in documentation/diplo_stuff.txt, Message timing.

1. The sitting seats every writer with mail waiting.
   Mail is its unread letters and every player's plain message still awaiting its answer.
   It also seats up to AI_LETTER_WRITERS_PER_TURN other writers.
   Countries that waited longest go first. letters_last_turn records the turn a country was served.
2. Each country reads its waiting mail, earlier letters, and its notebook.
   It writes up to AI_LETTERS_PER_CALL letters, one per country.
   Only players and model-driven AI countries can receive letters.
3. It gives each letter and message it read an opinion change.
   queries.add_opinion_change limits the change to AI_OPINION_CHANGE_MAX and adds it to the general relation modifier.
4. It rewrites its notebook, which is limited to AI_NOTEBOOK_LENGTH.
5. Its letters wait in session_state.queued_letters until the send phase.
   diplomacy_processor delivers them with players' text, after every AI phase of the turn.
   No country reads, answers, or proposes in reaction to them until the next turn.

A letter has letter: true on both copies. The reader's copy gets letter_read: true when its reader is served.
An unserved or failed sitting leaves letters unread for the next turn.
A letter that the model refers to in the third person is dropped.

A player's plain message to an AI has no letter field. Its delivered MSG: request marks it as awaiting an answer.
When the AI's sitting returns a usable reply, the sitting has answered the message, whether or not it wrote back.
session_state.letter_answers records this, and the response phase sends no reply of its own.
Otherwise, the response phase answers it with process_custom_message, as it answers messages to AI countries that do not write letters.
That reply's opinion_change uses the same limit as a letter's.

A letter does not change the game in any other way.
Agreements need proposals. The director reads the notebook and can make own-initiative proposals to correspondents.

nation_data["ai_notebook"] holds the notebook text. Real-time snapshots and tournament views remove it from other countries' records.
Older saves without these fields have no notebook and no read letters.

Read current tuning values in data/constants.py.
See documentation/non_llm_ai.txt, TUNING, for shared action limits.

SHARED PROMPT PREFIX
-------------------

Model requests in one turn must share the same world-context prefix.
build_world_context puts shared information first:
date, country list, politics, and world events.
It then adds the selected country, its territory, relations, and task.
The ai_director system prompt must not name a specific country.

ai_handler._combined_prompt puts user content before system content in one user message.
Every provider sends this combined prompt. It does not use a separate system field.
This order preserves shared text across letter, director, and response phases.
The letter prompt's system half must not name a specific country either.

Local models can reuse an unchanged prefix instead of processing the whole world again.
Hosted providers cache an unchanged prefix, which decreases its cost and delay.
Claude caches only to a marked block.
call_claude marks the end of the shared part, at ai_prompts.SHARED_CONTEXT_END.
A shared part below the model's minimum cache size is not cached.
tests/test_prompt_sharing.py protects this order.

call_ollama sets num_ctx to OLLAMA_CONTEXT_TOKENS for every request.
The Ollama default can be smaller than a world-map prompt. Ollama then cuts the prompt without an error.
A num_ctx change between requests makes Ollama load the model again.
call_ollama also sets keep_alive to OLLAMA_KEEP_ALIVE.
By default, Ollama unloads the model after five minutes, and a planning phase can take longer.
The next phase would then load the model again and read the whole world again.
Ollama is a separate program, so closing the game does not unload its model.
When the game quits, ai_handler.unload_ollama_models unloads every Ollama model that the session sent a request to.
FORCE SKIP AI also unloads the current model. A phase timeout does not.
Leave neutral relation scores out of the country-specific section.
State that an unlisted country is neutral.

See documentation/other/llm_benchmark_notes.txt for historical performance measurements.

TURN BUDGET AND CANCELLATION
---------------------------

ai_turn_budget_seconds sets the maximum model time for a complete turn.
Its default, 0, means no time limit.
FORCE SKIP AI lets the player end model work early.
Unfinished model work uses rule-based fallbacks.

With a positive limit, prepare_turn starts one shared clock.
The phases run in this order: letters, director, responses.
Each phase takes a share of the time left when it starts.
Unused time passes to the next phase. The final phase takes the remainder.

AI_BUDGET_SHARE_LETTERS, AI_BUDGET_SHARE_DIRECTOR, and AI_BUDGET_SHARE_RESPONSES define those shares.
Do not restart the full budget for each phase.
The letter sitting uses the letter phase's share.

The director is the LLM step that decides which diplomatic moves each AI country makes on its own initiative this turn.
The code calls it that because the country's leader (the LLM) directs its staff (the rule-based AI): the staff draws up a list of options,
and the leader picks from that list. The code is in ai_director.py, and the phase runs from start_proactive_llm_tasks and finish_proactive_llm_tasks in ai_diplomacy.py.

The director sends its requests after the rule-based proactive pass, with or without a limit.
Rule-based research, economy, and movement planning run while those requests are out.
After movement planning, the director collects the answers and carries out each country's choices.
Its share starts when its requests go out. When the share ends during movement planning, answers that arrived by then still count.
ai_llm_runner.start_llm_batch sends a batch, and LLMBatch.collect records its answers on the thread that collects them.
Build every prompt before the batch starts, because the turn thread changes nation_data while the requests are out.
A director prompt therefore shows the country's manpower and materials before its own rule-based spending in that turn.

A phase must do the following:

1. Reject time shares too small for useful work.
   run_llm_batch uses min_calls for this.

2. Stop abandoned network requests.
   future.cancel() cannot stop a running worker.
   shutdown(wait=False) does not interrupt a blocked read.
   ai_handler.abort_active_requests closes active sockets.
   It closes Ollama requests and every connection that the shared requests session opened.
   Gemini requests and requests through a proxy continue until they end.
   Do not unload the model for a phase timeout.
   Model unloading would discard the shared prefix cache.

3. Run rule-based proposal decisions outside the model batch.
   A slow model must not delay proposals that do not need it.
   Put the player's correspondence first in the remaining response queue.

call_ollama stops a reply that keeps repeating itself.
That check applies when the end of the reply is one block of text, such as a sentence or whitespace, repeated at least OLLAMA_REPEAT_COUNT times.
The reply becomes a provider error, and the caller uses its rule-based fallback.
Without this check, a looping local model writes until its context window is full.

ai_handler.typical_call_seconds estimates request time from completed calls.
It smooths measurements and ignores requests that the game interrupted.
An interrupted request returned None, or was in progress when abort_active_requests ran.
A request that failed for another reason is measured, because a slow provider can fail.
Do not replace it with an assumed fixed request duration.

FAIRNESS AND PROGRESS
--------------------

When time is limited, countries that waited longest go first.
nation_data["llm_last_turn"] records when a country was served.
Record the turn even if the response is unusable.
A failing provider must not keep one country at the front indefinitely.

When a batch cannot serve everyone, report the unfinished work and the setting that limits it.
Suggest ai_threads only for providers other than Ollama.
Several simultaneous generations on one local model can reduce speed.
A phase that declines an insufficient time share reports this in the console.

ai_threads limits simultaneous model calls. Its default and the local-provider fallback come from data/json/starting_defaults.json.
ai_turn_budget_seconds has no settings UI.
It is stored in the ignored data/json/settings_config.json.
Changing its value in starting_defaults.json does not replace an existing saved setting.

FORCE SKIP AI must be reachable in every phase that can block.
Show it when any model-work counter is nonzero.
Letters use letters_total.
trigger_ai_thread resets that counter with the other turn counters.

SHOW THREADS appears with FORCE SKIP AI while the AI phases run. It opens the model threads panel (ui/panels/llm_threads_panel.py).
The panel shows the current batch's phase and its running, waiting, finished, and skipped job counts.
It has one row per worker thread, with the thread's country, state, and running time.
The states are Waiting for model, Writing, Done, Failed, and Stopped.
Below the rows is the selected thread's model output. Ollama output appears as it streams.
Hosted providers do not stream, so their whole reply appears when it arrives.
map_logic/ai/ai_activity.py holds this record. ai_llm_runner opens one record per batch and one per job, and ai_handler adds the output.
begin_turn clears the previous turn's record. The record is display data and never changes a game rule.

The letter bar counts the countries in the turn's sitting.

Size the response progress bar from the actual queue.
Do not duplicate immersion rules to estimate its size.

At ABSOLUTE, check provider availability if turns are slow.
An unavailable Ollama server can make each request wait for its timeout.
A positive ai_turn_budget_seconds limits that waiting across the turn.
