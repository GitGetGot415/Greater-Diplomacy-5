TOURNAMENT FILE STORAGE
=======================

data/io/multiplayer_io.py owns tournament archive storage.
Hosts and country players load one shared, encrypted game snapshot.
Each country key decrypts a small record that contains the shared session key.
Adding country keys does not add copies of the map, images, or country data.
The public spectator key opens a separate spectator snapshot without the shared session key.

Country players receive the complete snapshot before local display restrictions apply.
Tournament fog and private-data restrictions depend on the game client.
Snapshots and player moves use compact JSON. Gzip compression applies before encryption when it reduces the payload size.
The loader also accepts older encrypted JSON without compression.
New compressed files require a game version with gzip decoding support.
Per-country snapshots and compressed snapshot differences are not supported.
Real-time multiplayer continues to filter each recipient's state before transmission.

Each tournament archive stores one turn. Its history field is null.
The loader ignores history in older tournament archives and removes temporary history files.
Province state is stored once, separately from map geometry.
Only terrain.png and id_map.png are embedded. The game rebuilds the political and cores layers.
Country records, messages, and last-turn unit reports remain complete.

Tournament move import
----------------------

Only the tournament host can use Load Moves.
Each rejected file opens a notification with its filename, country name when known, and rejection reason.
Tournament players also receive rejection details when they use Import Turn.
Long rejection details support scrolling.
Unreadable files, invalid keys, malformed data, unauthorized orders, wrong sessions, wrong turns, and duplicate submissions cannot be accepted.
Rejected files do not change host state.

Numeric differences in matched ground-unit statistics or new administrative durations require host review.
The comparison uses the host's current units and scenario settings.
Aircraft statistics remain under host control.
Aircraft cargo statistics also remain under host control.

Older units without stable IDs cannot be compared reliably.
Changed unit forms use different statistics and are excluded from this comparison.
This check does not prove that all submitted statistics or resource changes are valid.

After reading a stat notification, select Accept to import despite the stated risks.
Select Reject or press Escape to keep the move rejected.
Acceptance can import incorrect values or unfair advantages.
The importer reads and validates the file again before acceptance.
All checks for malformed data, permissions, sessions, turns, and duplicates still apply.

Duplicate checks cover all selected files and the associated review callbacks.
Separate imports can replace a country's earlier draft, as before.
The final notification gives accepted, rejected, and overridden counts.
Move files and saved games require no new fields.
These controls do not change real-time multiplayer or local game modes.

UNIT RANGE SETTINGS
===================

Select Edit Unit Stats in Scenario Settings. This button is right of Edit Construction Turns.
The Range category lists bombardment families and aircraft families from the complete unit library.
Disabled families remain available in this editor.

Bombardment range uses whole tiles. Each family has one range field.
Aircraft range uses whole map pixels. Each family has a starting range and an increase for each level.
Range = start + (level - 1) * increase.
Starting ranges must be positive. The increase can be zero.
The existing mission rules still convert aircraft range into strike, patrol, relocation, and air drop reach.
See documentation/air_stuff.txt for those rules.

Select Save All Changes to apply the draft. Back discards the draft.
Reset to Defaults restores and saves the library ranges after confirmation.
The Edit Unit Stats button shows ! when saved ranges differ from defaults.
The main Scenario Settings reset keeps these separate editor settings, as it does for construction turns.

Scenario settings store changed fields in unit_range_overrides, keyed by unit family.
Supported fields are bombard_range, air_range_start, and air_range_per_level.
data/queries.py validates and applies these fields when the map loads.
Missing or invalid fields use library defaults. Existing saves retain their own scenario settings.
Current defaults come from data/json/unit_data.json and the shared bombardment rules.
See data/generators/recipes.py and data/constants.py for source tuning.

Combat, AI, command validation, and previews read the same active unit library.
Saves and both multiplayer systems retain the host's range settings.
Only scenario setup can change ranges. Player move files and real-time player commands cannot change them.
Real-time lobby edits update the server's ranges before it sends new snapshots.
These settings apply to all local player modes, AI countries, and map editor units.

CONSTRUCTION TURN SETTINGS
==========================

Open the Construction Turns Editor from Scenario Settings.
The Conversions category has sliders for Truck / Ship Conversion and Air Drop Recovery.
Each slider accepts whole turns from 1 to 9. These actions remain enabled.
The truck and ship directions use the same duration.
See documentation/air_stuff.txt for recovery timing and restrictions.

Scenario settings store nondefault values in conversion_turn_overrides, keyed by the editor's action names.
data/queries.py owns the defaults, limits, and conversion-order helpers.
Older saves without these overrides use the constants in data/constants.py.
Saved games and multiplayer snapshots retain the scenario settings.
Only scenario setup changes these settings. Player move files cannot change the host's durations.
Pending orders retain their remaining turns.
The map editor's direct unit converter changes starting forms immediately.

REGULAR SAVE HISTORY
====================

data/map/history_io.py owns disk history storage.
history.json.gz contains compact JSON compressed with gzip.
The writer compares compressed full snapshots with compressed snapshot changes. It stores the smaller file.
Snapshot changes use the gd5-history-delta-v1 format identifier.
In that format, the first entry contains a complete snapshot. Later entries contain changes from the previous entry.
Dictionary changes preserve deletions and key order. List changes preserve edits, additions, and removals.
Snapshot changes omit unchanged messages, images, research, and units.
The reader restores separate, complete snapshots for the timeline and historical loading.
This format reduces disk storage. It does not reduce the full timeline's memory use.

Older plain history.json files and compressed full snapshots remain readable.
Saving an older game selects the smaller representation. No turns or messages are removed.
Delta history files require a game version with delta decoding support.
Regular metadata and map_data.json remain readable JSON.
Real-time commands and state filtering do not change. Real-time host saves use the same history writer.

PROJECT FILES
=============

AGENTS.md
    Repository rules for AI-assisted changes and maintenance preferences.

assets/
    Images and audio.

base_maps/
    Base maps used by the game.

context/
    Source export tools and development notes.
    The export script combines source files into a text file.

data/
    Game data and data tools.
    constants.py stores shared constants.
    queries.py provides shared queries about current game state.
    json/unit_data.json and json/building_data.json own current unit and building settings.
    json/research_template.json owns current research settings.
    generators/recipes.py defines data generation.
    Read current stats, costs, research settings, and capabilities from these sources instead of documentation.

documentation/
    Project guides and design notes.
    non_llm_ai.txt covers rule-based AI, combat, tactical play, spectators, and shared display rules.
    ai_movement.txt covers AI unit orders, movement caches, aircraft missions, attack checks, rotation, and movement tuning.
    llm_ai.txt covers model settings, legal choices, prompts, summits, budgets, cancellation, and fairness.
    diplo_stuff.txt covers diplomacy rules and message timing.
    air_stuff.txt covers aircraft rules.
    data_migrations.txt covers compatibility with older GD5 data.
    other/
        ai_responses_gd4_reference.txt contains archived Greater Diplomacy 4 response text.
        bypass_quarantine_macos.txt contains macOS quarantine instructions.
        recommended-relay-defaults.txt contains relay setup defaults.
        sandboxed_mods_info.txt describes sandboxed mods.

dist/
    Generated packages for distribution. Do not edit these as source.

map_logic/
    ai/
        Computer-controlled country behavior.
        ai_settings.py reads provider, model, and API-key settings.
        ai_handler.py manages request cancellation, turn IDs, and model providers.
        ai_evaluation.py selects replies to proposals, messages, and proactive actions.
        ai_diplomacy.py selects rule-based war, faction, and claim actions.
        ai_movement.py issues unit orders.
        ai_construction.py selects recruitment and construction.
    camera/
        Camera movement. This folder does not control camera tilt.
    diplomacy/
        Shared diplomacy rules and effects.
        war_actions.py, puppet_actions.py, and faction_actions.py own their respective actions.
        diplomacy_agreements.py exports those actions for compatibility with older callers.
        diplomacy_logic.py also exports agreement, processor, and message functions.
    random_map/
        Random map and scenario generation.
    rendering/
        Map rendering, UI bars, buttons, and symbols.
        symbol_loader caches symbol-name results and scaled images.
        overlay_renderer.UNIT_BOXES caches complete unit-box images.
        Treat shared cached images as read-only.
        Pass alpha to get_symbol instead of changing a shared image's alpha.
        Map culling checks both width and height.
        These caches reduce repeated work when many units use the same image.
    setup/
        Scenario setup and initial country selection.
    turn_processing/
        Turn resolution. This folder replaced the old system32/ folder.
        unit_events.py records unit events during turn resolution.
        It keeps only the last completed turn.

map_tools/
    Tools to create and test maps.
    validation/check_flags.py and check_adjectives.py check data/json/countries_data.json.
    interactive_map_tester.py is the interactive pygame map tester.
    Its earlier name was tester.py.
    automatic_map_painter.py and reset_map_data.py are separate map-authoring tools.

saves/
    Saved games.

scenarios/
    Scenario data.

screens/
    Complete game, menu, and editor screens.
    menu_screens/
        Main menu, settings, new-game setup, and other main navigation screens.
    map_related_screens/
        Screens opened from an active game.
        Examples include Orders, Battle, Research, Production, Mail, Economy, and diplomacy screens.
        battle_screen.py manages combat lanes.
        It replaces Give Orders on a tile where combat is active.
        combat_rules.py owns the combat model that this screen edits.
        See documentation/non_llm_ai.txt for combat controls and tactical permissions.
        unit_events_screen.py shows the last turn's unit events in a sortable table.
        country_summary.py shows read-only country information when the player clicks the top-left flag.
        See documentation/non_llm_ai.txt for summary data and visibility rules.
        See documentation/non_llm_ai.txt, LAST-TURN UNIT EVENTS, for controls, visibility, and persistence.

        Battle columns belong to combat sides, which can include several countries.
        The reserve column also shows allied units that the player cannot edit.
        Those units can replace losses in the front rank.
        draw_panes(foregrounds=) in ui/scroll_panes.py draws row flags and stat icons.
    editor_screens/
        Map editor screens.
        These cover economy, date, research, brushes, diplomacy, events, leaders, and turn settings.
        Brush and Paint buttons sit between Nation Brush and Load.
        These buttons apply only to territory and cores. Other tools keep their existing behavior.
        Brush changes tiles during a drag. Each editor session starts with Brush selected.
        Paint changes one connected land region per click. Water tiles stop the fill.
        Territory Paint matches the clicked tile's owner. Core Paint matches its complete core set, regardless of list order.
        Left-click applies the selected nation. Unclaimed clears cores.
        Right-click removes the selected nation's cores, or picks a territory owner.
        Undo and Redo apply to the complete fill. The selected tool is not saved.

ui/
    Shared widgets, bars, dialogs, popups, and event handling.
    Complete feature screens belong in screens/.
    flag_icons.py caches small national flags for country lists and combat rows.
    Each screen builds its own buttons.
    Map buttons belong in screens/menu_screens/map.py.
    Country-edit buttons belong in screens/map_related_screens/edit_country.py.
    Settings buttons belong in screens/menu_screens/settings.py.

    See documentation/non_llm_ai.txt for map unit filters and army-group display.
    The map tutorial uses image markers in UNIT_VIEW_NOTE in ui/confirm_dialog/message_box.py.
    Move a [icon:naval:18] marker to change its position.
    Change 18 to set the maximum image dimension in pixels.
    Use an icon name from ui_elements.UI_ICONS.
    Omit :18 to use the text height.
    Images keep their original proportions. Images stay with the preceding word when lines wrap.
    bars/ui_bars.py draws its shared textured bar.
    event_handler.py uses the same rectangle to block clicks through the bar.

    confirm_dialog/
        pygame dialogs that replace tkinter dialogs.
        base.py provides the shared dialog structure.
        yes_no.py, text_input.py, message_box.py, and person_info.py provide specific dialogs.
