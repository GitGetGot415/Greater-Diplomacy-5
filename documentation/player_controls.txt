PLAYER CONTROLS AND PERMISSIONS
===============================

CLASSIC UNIT ART
---------------

Classic unit images use each equipment stage's year, not the current game year.
Files in assets/classic can specify a year range, such as Infantry 1800-1899.png.
A plus sign sets an open end, such as Militia 1900+.png.
Alternate styles keep their own images. Missing images use the Classic fallback.
Restart the game after adding image files.

AI means artificial intelligence. UI means user interface.
See documentation/non_llm_ai.txt for AI decisions and shared combat rules.
See documentation/diplo_stuff.txt for diplomacy controls, timing, and effects.
See documentation/air_stuff.txt for aircraft controls and rules.

BUTTON DISPLAY
--------------

Shared buttons use shade bands and square checkerboard transitions.
Taller buttons add shades to keep bands approximately 10 pixels high.
Small buttons omit the checkerboard pattern. Very short buttons use fewer bands.
The inner bevel reverses while a button is pressed under the pointer.
Hover, selection, and disabled states keep their existing outlines and colors.
Editor color swatches keep their flat fills.
ui/widgets/ui_elements.py caches backgrounds by size, color, pressed state, outline width, and gradient strength.
The cache retains at most 128 backgrounds. Moving a button reuses its background.
This display change applies in all modes. It adds no saved fields or multiplayer commands.

PANELS AND CUSTOM CONTROLS
-------------------------

Dialogs, army controls, the tutorial, progress displays, and real-time match panels use the shared pixel shading.
Production queues, resource bars, message boxes, and mouse settings cards use the same square borders and bevels.
Shared modal panels also apply this appearance to their game and editor screens.

Text fields have recessed bevels. Active fields keep their existing focus borders.
Text-entry backgrounds use black fills with zero gradient strength by default.

Custom buttons keep hover, pressed, selected, and disabled states.
Color swatches and the custom emblem canvas keep their flat colors.

Opaque and translucent backgrounds use bounded caches in ui/widgets/ui_elements.py.
Progress bars clip cached fills. Moving panels and changing progress reuse cached shading.
The army tray and country-action list use shared scrollbar rendering.
The army tray scrollbar is six pixels wide. It stays beside the existing action buttons.

These changes affect display only. Click areas, keyboard controls, permissions, and game rules remain the same.
Saves and multiplayer commands retain their existing data.

Edit background colors and gradient strengths in ui/background_styles.py. All style tables described below use this shared file.
Keep layout and border settings in their existing UI modules.

Edit RESOURCE_BAR_STYLES for the full-width resource bar in Production, Orders, and other screens that use this bar.

Edit RESEARCH_PANEL_STYLES for timeline headers, research slots, and technology details.
The research timeline uses these styles in player, spectator, and country-editor modes.
Edit MUSIC_PANEL_STYLES for the music album pane and the playback header.

Each entry has color and gradient_strength fields. Zero gives a flat fill; one gives standard shading.

The inactive and active entries control shared text fields, including searches, rename boxes, and editor fields.
The dialog entry controls text-input dialogs. The message entry controls the message compose box.
Each entry has color and gradient_strength fields. Zero strength gives a flat fill; one keeps the standard contrast.

Higher strengths increase contrast. Positive strengths use the standard top-to-bottom shading direction.
The army name field keeps its color and gradient strength in ARMY_EDITOR_STYLES["name_field"].

Text colors, focus borders, and input controls remain unchanged.

Each entry has color and gradient_strength fields, as in MAP_BAR_STYLES.
Colors accept RGB tuples. A fourth value sets opacity from 0 to 255.
Gradient strength must be zero or greater. Zero gives a flat fill; one keeps the standard shading.

Restart the game after editing these values. These settings do not change buttons, text, or color swatches.

Edit ARMY_BUTTON_STYLES for army buttons and group cards.

The army_group entry controls the gradient of existing army cards. Their colors still come from each army's symbol color.
The unassigned entry controls the Unassigned box gradient. Its base color remains constants.UNASSIGNED_ARMY_COLOR.

They use the same gradient rules as the panel styles. Hover, pressed, and disabled states retain the selected gradient strength.
Restart the game after editing these values.

MAP FRAME DISPLAY
-----------------

The map's top, bottom, left, and unit-filter bars use rectangles drawn in code.
The bars use shade bands, square borders, and bevels from the shared button shading cache.
The bars do not load PNG backgrounds.
The existing panel visibility rules apply in player, spectator, tactical, editor, and multiplayer modes.

Edit MAP_BAR_STYLES in ui/background_styles.py to set each bar's color and gradient_strength.
The entries are top, bottom, left, unit_filter, and bottom_left. The bottom_left entry controls the raised bottom-left corner panel.

Set color to a red, green, blue (RGB) tuple. MAP_FRAME_COLOR provides the common default color.
Set gradient_strength to a nonnegative number. A value of 1.0 keeps the standard gradient.
A value of 0 gives a flat fill. A value above 1.0 increases the gradient contrast.

Gradient strength does not change borders or bevels. Restart the game after editing these values.

Edit MAP_CONFIRM_STYLES in the same file for map confirmation backgrounds.
The country entry controls the country selection confirmation. The exit entry controls the exit confirmation.
Each entry has color and gradient_strength fields, with the same rules as MAP_BAR_STYLES.

These settings change only the panel background. They do not change the buttons or the dimming behind the panel.
Restart the game after editing these values.

The province menu keeps assets/backgrounds/Province.png and caches the resized image for each viewport size.
Map input uses that image to block clicks under panels and permit clicks through the transparent map window.
The moving checkerboard squares use button shading.
This display change adds no saved fields or multiplayer commands.

SLIDER DISPLAY
--------------

Shared sliders and the music progress control use the cached button shade bands and square borders.
Tracks have recessed bevels. Handles have raised bevels.
The handle outline becomes white under the pointer or during dragging. Dragging reverses the handle bevel.

Edit SLIDER_STYLES in ui/background_styles.py for slider colors and gradient strengths.
The entries are track, handle, locked, and progress. Each entry has color and gradient_strength fields.
Slider colors use RGB tuples. Zero strength gives a flat fill; one keeps the standard shading.
Values above one increase contrast. Borders, bevels, and handle hover states keep their existing rules.
Restart the game after editing these values.

The locked entry controls restricted track sections. The progress entry controls the music progress fill.
The track and handle entries initially reference existing color defaults in data/constants.py.
Replace either reference with an RGB tuple to set its color in SLIDER_STYLES.
The politics position line uses the track color without a gradient.
Dragging, value limits, labels, and permissions remain the same in all modes.

SCROLLBAR DISPLAY
-----------------

Vertical and horizontal scrollbars use rectangular tracks and handles with the shared slider shading.
They use the track and handle entries in SLIDER_STYLES.
Handles have no grip lines. Scroll ranges and input remain the same.

These display changes apply in all modes. They add no saved fields or multiplayer commands.

COUNTRY SUMMARY
---------------

screens/game/country_summary.py shows the summary.

Hover over the flag in the top left to highlight it.
Click the flag to open that country's summary.
Select another country's land tile to show its flag and summary.
Selecting water keeps the current player's flag.
The summary is read-only. Back returns to the same player and selected tile.

Long summaries support the mouse wheel, scrollbar, Page Up, and Page Down.

Military shows the combined attack of available units with their current health and national damage modifiers.
Combat width, missions, and target defenses can change actual damage.

Foreign military figures include only visible units. They do not reveal hidden cargo.
Strategic players see their complete army. Tactical players keep their restricted battlefield visibility.
Local spectators and editors can see complete armies.

Politics shows the political position, direction, research modifier, and policy states.
Diplomacy shows the faction, leader, members, overlord, puppets, and enemies.
All country names use the shared display-name helper.

Economy shows stockpiles, income, expenses, and net income when the viewer can inspect private economics.
Text shows conscription and material conversion. The summary has no sliders.
Private economies hide these values as well as resource figures.
Players can inspect their own economy.
Faction members, direct puppets, and the overlord share economy figures in all game modes.
Other foreign economies require disabled fog, spectator mode, or editor mode in local games.
Other foreign economies remain private in both multiplayer systems.
Real-time clients receive shared totals from the server without private orders or research plans.
The Tournament Spectator cannot inspect private economics.

queries.get_country_summary prepares the screen's data when it opens.
queries.get_country_damage_multiplier owns the combined national damage modifier for summaries and combat.
Frame drawing and scrolling use cached presentation data.
The summary adds no saved fields or multiplayer commands. It does not change country state.
Flag inspection is unavailable during country selection, hidden UI, turn processing, saving, and blocking confirmations.

TACTICAL PLAY
-------------

A tactical player commands one division.
The host country remains AI-controlled.
queries.get_active_ai_nations removes the human-country exclusion while tactical_mode is active.

- The AI cannot disband the player's division.
- Orders and Battle allow edits only to that division.
  They still display other country units.
- Diplomatic popups for the host's inbox do not interrupt tactical play.
  diplomatic_popups.spawn_popups_for_player still marks those messages as shown.
  This prevents old host messages from appearing after the player declares independence.

Declaring independence ends tactical mode.
map_screen.player_unit can remain after that change.
Always check the mode instead of inferring it from the attribute.

RESEARCH DISPLAY SETTINGS
-------------------------

data/json/research_display.json contains research button sizes, icon scales, layout values, and bundled art-style adjustments.
Restart the game after you edit this file. The game reads it once and caches the data.
These settings apply to player, spectator, and map-editor research timelines.
They do not change gameplay, permissions, saved games, or multiplayer commands.

button_sizes defines named presets as [width, height] in pixels.
defaults selects a button_size and an icon_scale.
defaults.large_icon_scale applies to technologies that unlock buildings in constants.LARGE_ICON_BUILDING_GROUPS.
An icon_scale multiplies the existing symbol zoom. It does not specify a pixel size.
Button dimensions and icon scales are independent. Icons keep their proportions.

The game applies settings in this order:
1. Apply defaults. Select large_icon_scale when the unlocked building requires it.
2. Apply the matching categories entry, such as NAVY.
3. Apply the technologies entry for the technology key, such as railgun.
4. Apply that technology's levels entry for the exact level, such as "2".
5. Apply art-style multipliers.

Each category, technology, or level entry can specify button_size, icon_scale, or both.
button_size accepts a named preset or an explicit [width, height] pair.
Technology entries use keys from the active research library. Display-name changes do not select different sizes.
Level entries override only that level. Later levels use their own settings or the technology settings.
Unlisted technologies and categories use defaults. Unlisted fields retain the preceding settings.

For example, this technology entry sets an explicit button size and icon scale:
"railgun": {"button_size": [420, 180], "icon_scale": 1.5}

layout.row_y contains six row positions. layout.default_row_y positions technologies without an assigned row.
layout.row_center_offset locates each row's center relative to its position.
Button centers and connection anchors use the same offset.
layout.pixels_per_year sets horizontal timeline spacing. layout.modal_icon_box sets the detail popup's icon box.
Increase row or timeline spacing if larger buttons overlap. The game does not arrange rows automatically.

styles contains the bundled art adjustments, including Classic. Each key names an art style.
button_scale multiplies all button dimensions while that style is active.
button_scale_overrides applies additional width and height multipliers to a resolved symbol key or family.
icon_scales applies additional icon multipliers by relative image filename, including culture subfolders.
Filenames can contain wildcard patterns, such as Infantry*.png. An exact filename takes priority over patterns.
If several patterns match, the first pattern takes priority.
Classic filenames use the symbol name with .png. Classic Infantry*.png and Militia*.png rules double their research icons.
These image-specific adjustments follow the actual image's style and country variant.
Classic fallback images use the Classic rules, including when another art style is selected.

Optional assets/<style>/research_scale.json files remain supported for custom styles.
Their entries override matching central style entries. Unspecified entries retain the central values.
Use the central file for bundled sizing changes.
The map, production screens, and research category tabs do not use these node settings.

RESEARCH EDITING
----------------

The Infantry category uses named equipment stages for infantry, cavalry, militia, and artillery.
Each stage has numbered upgrades. Vehicle unlocks appear on a separate row below cavalry.
Technology details show the units unlocked by each stage.
All stages use existing images. Vehicle infantry statistics come from regular infantry and shared generation rules.
See documentation/non_llm_ai.txt, HISTORICAL INFANTRY EQUIPMENT, for shared equipment and upgrade rules.

The editor's research screen sets a country's starting research.
Select a country in Map Research Editor to open its research timeline and category tabs.
Click an incomplete technology level to grant it and its prerequisites immediately.
This also grants earlier levels in the same technology.
For an OR requirement, keep a completed branch or add the branch that needs the fewest additional levels.

Click a completed level to remove it and later levels in the same technology.
Remove dependent levels only when their remaining prerequisites no longer permit them.
Another completed OR branch can preserve a dependent technology.
Clear changed research projects and progress that no longer meets prerequisites.
These controls change only the selected country. They do not change the map default.

In the map research editor, purple marks the exact default level when it is missing.
Pink marks that level when it is completed.
Earlier and later levels keep their normal colors.
Player and spectator research trees do not use these default colors.
The Completed tab is a text list. It has no technology edit buttons.

Edit ALL (Bulk) and Edit Map Default keep their separate Save controls.
Starting research editing requires the local map editor.
It is unavailable in tactical play, tournament multiplayer, and real-time multiplayer.

A spectator selects a country and sees its live research tree and queue.
Select View or Edit above the country search box before selecting a country.
View opens technology details without allowing research changes.
Edit previews technology changes, with the same prerequisite rules as the map editor.
The spectator research permission switch must permit Edit.
Tactical play and both multiplayer systems permit only View.

Select Exit or press the Back key to open the exit popup.
Select Save to apply the draft and leave the research screen.
Select Cancel to discard all edits and leave the research screen.
Select Go back to close the popup and keep the draft open.
The Back key and Escape also select Go back in this popup.
Draft changes do not change the country's saved research or progress.

An edit that discards active or paused research opens a Yes or No confirmation.
The message identifies the affected technologies and warns that progress will be lost.
Select No to keep the draft unchanged.
Select Yes to discard that progress in the draft.
Changing technologies back cannot restore this progress.
Cancel the entire edit to preserve the original research and progress.

Save checks permissions again and rejects changes if live research changed during editing.
A normal player sees their own research.
map_screen.viewing_research_country passes the selected country to the research screen.
map_screen.viewing_research_mode passes View or Edit. This temporary display choice is not saved.
editing_country serves the same purpose for the identity editor.

LAST-TURN UNIT EVENTS
---------------------

screens/game/unit_events_screen.py shows the sortable report.

The yellow mail button beside the resources opens Unit events.
The orange screen lists unit names, tile IDs, events, health changes, and sources.
Each unit name has its country's flag on the left.
The flag uses the owner recorded in the event, including events for destroyed units.
Click a column header to sort the table.
Click a row to read its full details.

The Details column and expanded view show country flags before identified unit names.
Damage received and damage dealt identify all units involved, even when they are hidden.
Hidden units keep their names and flags, but their province number shows ???.

Use the mouse wheel or Page Up and Page Down to scroll long expanded details.
Flag images and detail text are prepared when the screen or expanded view opens.

Filter events appears to the left of Mark all unread.
Select one event type to show only matching entries.
Select No filter to show all permitted entries.
The button is orange with a selected filter and blue without one.
The selection stays when you reopen the report during the same turn.
Each completed turn clears the filter, including turns received by real-time clients.

The picker disables choices that would show no entries for the current viewer.
Available choices stay blue, including the selected event type.
Search keeps these states. Enter selects the first available search result.

The filter changes only the local display. Saves and multiplayer commands do not include it.
Opening the report and Mark all unread still affect all entries permitted for the current player.

map_logic/system32/unit_events.py records actual turn resolution, including losses and attacks by AI units.
AI plans and combat forecasts do not write entries.
Damage dealt uses each source's share of the applied volley.
Shares include target restrictions and combat modifiers.
The total credit equals the target's actual health loss.
It excludes damage beyond the target's remaining health.

Events also include destruction, disbanding, deployment, movement, repairs, upgrades, and transport or type changes.
Destroyed units remain in the report after removal from the map.
Normal players see their own units.
Tactical players see only their selected division, including its loss.
Normal spectators can see all recorded entries.
Editors and tournament spectators receive no unit reports.

The badge counts unread entries for the current player.
Opening the report marks those entries as read.
Click Mark all unread in the report to restore the current player's unread badge.
Closing the report keeps this unread status. Opening it again marks the entries as read.
Hotseat players have separate read status.
The next completed turn replaces the report and clears old read status.
Empty turns therefore remove earlier entries too.

Saves retain only the latest report and its local read status.
Older saves start with an empty report.
History snapshots do not store copies of reports.
Tournament archives retain all entries in the shared host and player snapshot.
The tournament report screen shows only the receiving player's entries.
Real-time snapshots include only the receiving player's entries.
Combat details hide unit positions with ??? when the viewer cannot see the unit.
Player move files and real-time commands cannot replace host reports.
Real-time broadcasts preserve local read status for the same turn.

Each new damage entry can include detail_parts with text fragments and identified units' recorded owners.
Saves, tournament exports, and real-time snapshots retain these fragments.
unit_events.normalize_log validates the fragments and preserves the original details text.
Old reports without detail_parts keep plain text for other units until the next completed turn.
Their main unit still has its recorded owner's flag.
Existing Unknown unit entries cannot recover identities omitted by older recording rules.

MAP DISPLAY
-----------

Display defaults:

- Strategic country selection: Political layer, country names on, Units off.
- Tactical country selection and play: Units on, country names off.
- Normal strategic play and loaded games: start with Units on and country names off.

Tactical rendering draws every visible division at every zoom.
Do not apply strategic fading or zoomed-out army compression.
In tactical country selection, a clicked unit box selects from that box's divisions.
Fall back to the tile only when no rendered box exists there.

Map refreshes calculate layer inputs when game state changes.
They reuse pixel surfaces that have not changed.
Fog updates current visibility even when it can reuse its image.
Hotseat blanking and player changes still apply.

After all local players submit orders, the viewer becomes n/a while AI moves are prepared.
The AI preview must keep Resolve Turn, Settings, and Music available.
Country-owned actions remain hidden because no player country is assigned.
Hide Resolve Turn while AI preparation, map refresh, or saving is active.

Editor painting invalidates the affected surface.
Refresh Maps forces a full rebuild.
Planning-frame rendering does not run map-wide calculations.

In Economy view, factory icons turn gray while their province has units in production.
Factories without queued units keep their normal colors.
This display uses cached production status and does not depend on the Units view filter.
Partial fog keeps the existing unknown building marker.

Naval, Land, Air, and All form a vertical strip beside the lower left sidebar in Units view.
They filter local unit stacks, army markers, and order arrows.
Filter results are cached when load, state, or input changes.
Hover previews list only visible units that match the selected category.
Training icons use the queued unit's category, even when the province has no deployed units.
Training icons do not depend on deployed unit boxes or compact markers.
Hidden or partially visible provinces do not show training icons.
Clicking a province still shows its full visible unit list.
The filter uses the unit's current form.
Convoys are naval, including transported aircraft. Trucks are land.
All is selected when a game opens.

Click Hide above the strip to hide its buttons and background. The toggle moves down to the bottom-left controls.
Click Show to open the strip again. The toggle moves back above the strip.
The toggle, buttons, and background slide for 0.1 seconds when the strip opens or closes.
The filter buttons cannot be selected while the strip moves.
The selected filter stays active while the strip is hidden. Each new map session starts with the strip open.
This is a local display choice. Saves and multiplayer files do not store it.

Changing the filter clears local unit selection and compression animations.
It does not change units, orders, AI decisions, fog permissions, saves, or multiplayer commands.
Combat markers for matching units still estimate the complete battle.
Unknown fogged stacks and generic combat markers appear only in All.
Changing filters must not reveal hidden unit types.

The bubble color uses the predicted winner among countries that participate in combat.
Countries outside the combat lanes cannot determine the color, regardless of their health.
The forecast ranks surviving participants by health, then attack, then speed.
An unresolved forecast or a battle without surviving participants uses grey.

Map boxes separate land, naval, and air units, including members of the same army.
See documentation/air_stuff.txt, Mission controls, for aircraft grouping, mission badges, and strategic markers.

The display cache refreshes when orders, unit forms, filters, or the viewer change.

MAP EDITOR PAINTING
-------------------

Brush and Paint buttons sit between Nation Brush and Load.
These buttons apply only to territory and cores. Other tools keep their existing behavior.
Brush changes tiles during a drag. Each editor session starts with Brush selected.
Paint changes one connected land region per click. Water tiles stop the fill.
Territory Paint matches the clicked tile's owner. Core Paint matches its complete core set, regardless of list order.
Left-click applies the selected nation. Unclaimed clears cores.
Right-click removes the selected nation's cores, or picks a territory owner.
Undo and Redo apply to the complete fill. The selected tool is not saved.
