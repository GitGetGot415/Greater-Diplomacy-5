# Greater Diplomacy 4 to Greater Diplomacy 5 saves

GD5 can import a standard Greater Diplomacy 4 (GD4) save from the **Translate
Maps → Greater Diplomacy 4** screen. This is deliberately a one-way import:
it creates a new, collision-safe folder under `saves/` and never changes the
selected GD4 file. Open the created save from **Load Game**.

## Supported inputs

The importer accepts both forms written by the TurboWarp GD4 project:

- TurboWarp LZ-String `Base64` save text.
- The same save after it has been decompressed to text.

It validates the GD4 divider (`⎚`, U+239A), all 65 save sections, and the
standard 458-country/564-province record counts. Custom maps, altered country
lists, and saves with a different province count are rejected rather than
being guessed at.

## Map and state conversion

Every import starts from GD5's bundled `GD4` base map. The canonical mapping
tables in `map_logic/gd4_translation.py` map the standard GD4 country codes
and the 547 Earth province indices to that map. GD4's 17 moon records are not
represented in GD5. Two legacy Earth records have no current GD5 tile and are
also skipped. The GD5 political overlay is regenerated by the normal map
loader when the new save is opened.

The importer preserves recognised country names and leader title/name, province
ownership, factories, forts, and the four supported resources: Iron, Coal, Oil,
and Wheat. A GD4 resource amount is multiplied by 50 and rounded to an integer
in GD5. Factories become `Factory Lvl N`, forts become `Fort Lvl N`, and valid
GD4 friendship and war entries become symmetric GD5 alliances and wars.

GD4 time is stored as `year * 12 + zero-based month`. An import uses the 15th
of that month, starts with `total_turns` at 0, and sets turns to 30 days. GD5's
time-appropriate research is applied for the imported year; partial GD4
research is not copied. The country selected by the GD4 player is carried into
GD5 as the player country. If an older GD4 save does not contain a valid selected
country, the importer chooses a country that owns land so the GD5 gameplay UI
always has a valid player.

Troops become `Infantry Type <imported year>`:

- Each complete 100,000 GD4 troops becomes one full-health infantry unit.
- A non-zero remainder becomes one more infantry unit with health equal to
  `remainder / 100,000` of maximum health. For example, 10,000 troops become
  one infantry unit at 10% health.

If an exact infantry year is not in GD5's unit library, the nearest supported
infantry year is used.

## Intentionally omitted data

The import does not carry GD4 money, partial research, passive-income/fort/naval
research, naval units or connections, devastation, production queues, artillery
targets, mail, flags, portraits, GD4 color effects, or moon/unsupported
provinces. Destination country colors and base-map country resource balances come
from GD5's existing GD4 map.

## Maintaining the importer

`map_logic/gd4_translation.py` is UI-independent so its decoder and payload
builder can be tested without opening the game. If GD4's standard TurboWarp
map changes, update both `GD4_COUNTRY_CODES` and `GD4_PROVINCE_TO_GD5` from the
new project data, then update the associated tests. Keep the country and
province count validation in sync with those canonical tables; do not silently
accept a custom GD4 map, because its indices would point at the wrong GD5
territories.
